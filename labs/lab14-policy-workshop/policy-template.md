# AI-Use Policy — Ocotillo Engineering Group *(fictional firm)*

**Drafted by (team):** ______________________ **Date:** ____________ **Policy owner:** ____________ **Next review:** ____________

*Target: one page, about 400–500 words. Two to four specific sentences per section (§1 and §9 can be one or two). Name roles, time limits, and tools — vague rules ("use AI responsibly") cannot be applied. Each role writes two sections; the role is shown in brackets. These are the same nine parts as the Week 14 lecture checklist.*

---

**§1 Purpose and scope** [managing principal]. Who does this policy cover (employees, interns, subconsultants)? Which tools (chatbots, note-taking apps, coding assistants, image generators, AI features inside design software)? Why does the firm have it?

&nbsp;

**§2 Approved tools** [risk & IT lead]. Which tools are approved, for what? How does a new tool get approved? May personal accounts be used at all?

&nbsp;

**§3 Data classification — what may go where** [risk & IT lead]. Fill in the table (**yes** / **no** / **ask** = only with written project-manager approval, and only if the client contract allows). Then add what to do when unsure, and any special rules.

| Data class (examples) | Public AI tool (free/personal account: chatbots, note-taking apps, image generators) | Enterprise AI (firm-licensed, data contract) | Local model (runs only on a firm computer) |
|---|---|---|---|
| **Public** — OSHA rules, published zoning code, firm website | | | |
| **Internal** — firm templates, training slides, draft marketing | | | |
| **Confidential (client)** — client drawings, calcs, geotech reports, fees, RFIs, project photos, meeting notes | | | |
| **Restricted (personal & security-sensitive)** — personal data, recordings of people, security details of buildings and infrastructure, passwords | | | |

&nbsp;

**§4 Verification and review** [quality lead]. How must AI-assisted work be checked before it is used or sent? Who reviews it? (Restate · Units & magnitude · Independent check · Sources · Test & document.)

&nbsp;

**§5 Disclosure to clients** [client lead]. When and how do you tell clients about AI use? How are AI-generated images labeled? What about recording or transcribing meetings?

&nbsp;

**§6 Training** [client lead]. Who is trained, when, and on what?

&nbsp;

**§7 Accountability and responsible charge** [quality lead]. Who is responsible for AI-assisted work — the user, the project manager, the engineer who seals it? Can an AI tool ever approve or seal work?

&nbsp;

**§8 Incident reporting** [managing principal]. What must be reported, to whom, and how fast? What happens next? How do you make people willing to report mistakes?

&nbsp;

**§9 Review cycle** [managing principal]. Who owns the policy? How often is it reviewed, and what triggers an early review (an incident, a new tool, a new contract requirement, a change in law)?

&nbsp;

*Team of 3: skip the client lead; the quality lead also writes §5 and the risk & IT lead also writes §6.*
